# §3.15 Headers + Settings Single-Sourcing — Hardening Report (2026-09-02)

## Scope
1. Permissions-Policy header (server/app.ts)
2. CSP report-uri/report-to support via optional `CSP_REPORT_URI` env
3. Single-source `useStoreSettings` / store-name fallback literals

## Findings
- **Permissions-Policy** was already implemented in a prior headers cluster (helmet v8 dropped its middleware, so it is set manually in `server/app.ts`): `camera=(), geolocation=(), microphone=(), payment=(), usb=(), interest-cohort=()`. Kept as-is: stricter than the spec suggestion (`payment=()` vs `(self)`); the store never uses the Payment Request API (Zarinpal/Saman gateway redirects).
- **CSP reporting** was partially done: `reportUri: ["/api/csp-report"]` was hardcoded, plus per-request `Reporting-Endpoints: csp-endpoint=...` header and a rate-limited `/api/csp-report` 204 sink.
- **Settings fallback** was already single-sourced in `src/lib/constants.ts` (`STORE_SETTINGS_DEFAULTS`), consumed by server (`routes/settings.ts`, `routes/admin.ts`), `useStoreSettings`, admin `Settings.tsx`, and `Home.tsx`. Remaining duplicates were two `'جانبی آرنا'` literals in `src/pages/ProductDetail.tsx`.

## Changes (commit `1cd3b12`)
- `server/app.ts`: `reportUri` directive emitted ONLY when `process.env.CSP_REPORT_URI` is set (spread-omitted otherwise; no placeholder in code). `reportTo` + Reporting-Endpoints stay unconditional. Note: when the env var is unset the live CSP will intentionally NOT contain `report-uri` — the modern report-to transport remains the observability path.
- `src/pages/ProductDetail.tsx`: JSON-LD seller name and navigator.share title now use `STORE_SETTINGS_DEFAULTS.storeName`. Zero behavior change (same value).
